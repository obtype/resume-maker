# Derive link targets at render time

The CV content model stores contact details and prose as plain strings, and the app keeps content separate from presentation. Recognising links, however, is a parse of text the model returned, not a fact the user authored — and the model's output format is unreliable (markdown links, bare domains, redirect wrappers). We decided to derive link targets while rendering a field rather than storing structured URLs in the CV content, so that every stored CV, old or new, gains clickable links with no schema change or migration. The cost is that a link's URL is not first-class data: once the user edits a linked field, only the saved field HTML retains the target, and a later content-only regeneration replaces it. Revisit this if links need to be authored or edited directly, or if a renderer must style links differently per target.
