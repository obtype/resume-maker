# One prompt for multiple deliverables

A project used to produce exactly one CV from one prompt. Adding a cover letter, a cold email, and a LinkedIn message created a choice: one prompt per deliverable (simple, isolated, but repeats the PDR and job description) or one prompt for all selected deliverables (token-efficient, but the response shape and prompt structure become more complex). We chose one prompt per selection, because avoiding repeated context is the point of the feature and the app already treats the prompt as a first-class artifact. Two consequences are deliberately non-obvious: a CV-only request keeps the existing bare-CV response so every saved prompt and the existing Response path continue to work, while any other selection returns one JSON envelope with per-deliverable keys; and the static prompt text is split into a shared context template plus one task template per deliverable, so combined prompts do not duplicate context and editing one deliverable's rules cannot damage another's. Revisit the envelope if a future model or provider requires streaming per deliverable, or if the template model is replaced by a structured prompt builder.
